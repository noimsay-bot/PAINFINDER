3. 주요 파일
============================================================

- app/page.tsx
  전체 대시보드 UI와 클라이언트 상태를 담당함.
  메뉴: 오늘의 후보, 반복 신호, 실행 설정, 보류함, 실행 로그.

- app/globals.css
  전체 UI 스타일. 이전 요청에 따라 전반적인 글자 크기를 키운 상태.

- lib/pipeline.ts
  실행 설정 정규화, 검색어 전달, 소스별 수집, 중복 제거, 잡음 제거,
  공급자 독립 1차/2차 분석, 경쟁 검색, 점수 계산, Supabase 저장을 담당함.

- lib/llm/
  index.ts가 LLM_PROVIDER에 따라 공급자를 선택함.
  openai.ts는 Chat Completions와 오류별 최대 1회 재시도를 구현함.
  anthropic.ts는 기존 Anthropic 구현을 롤백용으로 보존함.
  pricing.ts는 실제 입력/출력 토큰 기반 비용을 계산함.
  types.ts는 공통 LlmProvider 인터페이스와 오류 형식을 정의함.

- lib/naver.ts
  네이버 검색 API 호출과 HTML 엔티티/태그 정리.

- lib/limits.ts
  실행당 검색어, 소스별 수집량, LLM 호출 수, 비용의 기본/하드 상한.

- app/api/run/route.ts
  수동 실행 API. 파이프라인을 실행하고 결과를 Supabase에 저장함.

- app/api/cron/route.ts
  CRON_SECRET Bearer 인증 후 기본 설정을 읽어 자동 실행함.

- app/api/dashboard/route.ts
  Supabase의 실제 후보/점수/경쟁사/판정/실행 로그를 UI 형식으로 변환함.

- app/api/configs/route.ts
  실행 설정 조회 및 저장.

- app/api/decisions/route.ts
  tracking, holding, rejected, unreviewed 판정을 Supabase에 추가 저장함.

- supabase/schema.sql
  run_configs, seed_queries, run_logs, raw_items, pain_points,
  competitors, scores, decisions 테이블과 인덱스 정의.

- vercel.json
  Next.js 빌드 설정과 매일 23:00 UTC(한국시간 오전 8시) Cron 설정.

5. 직접 검색어 방식의 데이터 흐름
============================================================

1) 사용자가 app/page.tsx에서 검색어 목록을 등록함.
2) /api/run 요청 본문의 `queries` 배열로 전달함.
3) normalizeConfig가 공백 제거, 빈 값 제거, 중복 제거를 수행함.
4) makeQueries는 queries를 수정하지 않고 최대 실행 개수까지만 자름.
5) 선택한 각 소스에 각 검색어를 그대로 전달함.
6) 수집된 결과는 source + source_id 기준으로 중복 제거함.
7) 짧은 글, 광고성 문구, 제외 분야 등 잡음을 코드 규칙으로 제거함.
8) Anthropic Haiku가 1차 후보 판정을 수행함.
9) 통과 항목을 Haiku가 구조화 분석함.
10) 네이버 웹 검색으로 경쟁 제품을 확인함.
11) raw_items, pain_points, scores, competitors, run_logs에 저장함.

DB 호환성 메모:
- Supabase run_configs 테이블에는 아직 `queries` 컬럼이 없음.
- 새 검색어 배열은 기존 `domains` JSONB 컬럼에 저장함.
- normalizeConfig는 `queries`가 없으면 기존 `domains` 값을 검색어로 읽음.
- 따라서 현재 DB 스키마 변경 없이 동작하며, 기존 domains 값도 이제 정확한 검색어로 취급됨.

9. 알려진 구현 한계 / 다음 작업 권장 순서
============================================================

우선순위 1: 하드 상한 입력을 실제 상태와 연결
- 현재 UI의 소스별 수집 상한과 일일 비용 상한 input은 시각 요소만 있음.
- configBody는 itemsPerSource 500, dailyCostUsd 3으로 고정 전달함.
- 사용자가 숫자를 바꾸어도 현재 실행에는 반영되지 않음.
- React state로 연결해야 함.

우선순위 2: 설정 저장/불러오기 완성
- 설정 저장은 매번 run_configs에 새 row를 추가함.
- 저장된 설정을 UI에서 다시 불러오거나 수정하는 기능은 없음.
- UI를 새로 열면 검색어 목록은 다시 빈 배열에서 시작함.
- 실행 설정 POST는 is_default=false로 저장함.

우선순위 3: Cron 기본 설정 처리
- /api/cron은 is_default=true 설정 1개를 찾음.
- 현재 UI 저장은 is_default=false이므로 자동 실행용 기본 설정이 없을 수 있음.
- 검색어 없는 설정으로 Cron이 실행되면 `검색어를 1개 이상 입력해 주세요.` 오류가 발생함.
- 기본 설정 지정 UI/API 또는 명확한 fallback이 필요함.

우선순위 4: 검색 기간 실제 적용
- period_days는 설정 구조에 존재하지만 수집 결과 필터링에 실제 사용되지 않음.
- 오해 방지를 위해 현재 UI에서는 기간 선택을 제거함.

우선순위 5: 소스별 완성도
- 네이버카페/지식iN/블로그/웹문서: 구현됨.
- HN: 구현됨. 한국어 검색어의 실효성은 낮을 수 있음.
- Threads: 코드 구현됨. 액세스 토큰 필요.
- 앱 리뷰: 수집 코드가 있지만 앱 목록 관리 UI는 없고 현재 검색어 UI에서는 소스 선택을 제거함.

우선순위 6: 모델 설정 정리
- model_stage1/model_stage2는 공급자 선택 후 실제 LLM 호출에 사용됨.
- DB의 기존 Claude 모델명은 읽을 때 OpenAI 단계별 모델로 자동 치환됨.
- model_verify는 경쟁 후보 최대 10건을 product/content/irrelevant로 배치 분류할 때 사용됨.
- 이전 모델 선택 UI는 실제 state와 연결되지 않아 이번 단순화 때 제거함.

우선순위 7: 추가 모델 가격 관리
- gpt-5.4-mini와 gpt-5.5 계열 가격은 lib/llm/pricing.ts에 등록됨.
- 가격이 등록되지 않은 모델은 비용 0으로 처리하고 warning:pricing 로그를 남김.
- 새 모델을 환경변수로 지정할 때 pricing.ts에도 단가를 추가할 것.
